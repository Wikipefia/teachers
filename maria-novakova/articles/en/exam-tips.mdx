# How to Ace Programming Exams

Our programming exams test understanding, not memorization. Here's how to prepare effectively.

## Exam Format

<Tabs>
<Tab label="Written Exam">
| Section | Weight | Description |
|---|---|---|
| Multiple Choice | 20% | Conceptual questions |
| Code Reading | 30% | Trace execution, find bugs |
| Code Writing | 50% | Implement algorithms from scratch |

**Duration**: 2 hours. **Allowed**: No materials.
</Tab>

<Tab label="Practical Exam">
| Task | Weight | Description |
|---|---|---|

| Code Quality | 20% | Clean code, good naming, edge cases |

**Duration**: 3 hours. **Allowed**: IDE, standard library docs.
</Tab>
</Tabs>

## The Code Writing Strategy

When facing a coding problem, resist the urge to start writing immediately.

<Callout type="warning">
**The #1 exam mistake**: Students start coding before understanding the problem. Spend the first 2–3 minutes reading, re-reading, and identifying edge cases.
</Callout>

### Step-by-Step Approach

1. **Read** the problem twice
2. **Identify** input/output types and constraints
3. **Think** of 2–3 small test cases (including edge cases)
4. **Plan** your algorithm in plain English
5. **Code** the solution
6. **Trace** through your test cases mentally

### Example: Two Sum

<CodePlayground language="python">
def two_sum(nums: list[int], target: int) -> list[int]:
    """Find indices of two numbers that add to target.

    Strategy: Use a hash map for O(n) lookup.
    """
    seen = {}  # value -> index

    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i

    return []  # no solution found

# Test cases
print(two_sum([2, 7, 11, 15], 9))   # [0, 1]
print(two_sum([3, 2, 4], 6))         # [1, 2]
print(two_sum([3, 3], 6))            # [0, 1]
print(two_sum([], 5))                # [] (edge: empty)
print(two_sum([1], 2))               # [] (edge: single element)
</CodePlayground>

Always mentally test with these:

## Common Pitfalls

<Callout type="error">
**Off-by-one errors**: When looping `range(n)` vs `range(n+1)` vs `range(1, n)`. Always double-check your loop bounds with a small example.
</Callout>

<Callout type="error">
**Mutating while iterating**: Never modify a list while iterating over it. Create a new list or collect indices first.
</Callout>
